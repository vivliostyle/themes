# 構成適用の失敗時の取り扱い {#adr-apply-failure}

---

ステータス：承認済　2025-12-16

## 背景

拠点エージェントは受け取った差分を順に適用する。失敗したときの扱いが定まっておらず、古い構成のまま取得を繰り返す拠点が2件あった。

失敗を検知できないまま日をまたぐと、構成不一致の障害と見分けがつかない。

## 決定

適用は1リビジョンずつ行い、失敗した拠点は直前の成功リビジョンへ戻したうえで隔離する。

- 単位：1リビジョンずつ適用し、途中で止めない
- 戻し：失敗したら直前の成功リビジョンを再適用する
- 隔離：3回続けて失敗したら取得を止め、監視へ通知する

```sh title="隔離された拠点の確認"
cfgctl status --state quarantined
cfgctl apply --site tsk-0412 --rev 4198
```

<div class="note">

隔離は自動では解けない。原因を確かめたうえで`cfgctl resume`で戻す。

失敗の回数は拠点ごとに数え、適用が通れば0に戻す。

</div>

## 影響

隔離は拠点を切り離す措置ではなく、取得だけを止める措置である。

- 隔離された拠点は古い構成で動き続けるが、状態は監視から見える
- 戻し先のリビジョンは<a href="adr-minimal-04.html#adr-storage" data-ref="adr"></a>の追記のみの履歴から取れる
- 隔離中の拠点も5年の履歴保全の対象から外れない
- 解除の判断と時刻は運用の記録に残す
