# はじめに {#intro}

この本は、社内で起きた3つの障害を、当事者の柊と聞き手役の真砂が振り返った記録です。ポストモーテムの会で録音した対話を、読みやすい分量に編集してまとめました。

3つとも、原因はいつも疑う場所にはありませんでした。監視は異常なしを示し、テストはすべて通り、コードにも誤りはありません。それでもサービスは止まり、集計値は狂い、ビルドは失敗しました。犯人探しの本ではありません。行き詰まった二人が、どこで問いの立て方を変えたのか。この本が残したいのは、その一点だけです。

## この本の読み方

太字の名前の付いた段落が、二人の発言です。名前は左の余白に出してあるので、誰の発言かを確かめたいときは、左端の名前を上からたどれば分かります。

字下げしたグレーの段落は編集部の補足です。当日の記録やあとで分かった事実のうち、対話では触れなかったものを補いました。対話の途中に挟んでありますが、飛ばしても話の筋は追えます。

社名、製品名、社内の呼び名はすべて伏せ、一般的な言い方に置き換えています。レジストリ、CI、キュー、ワーカーといった味気ない用語ばかりが並ぶのはそのためです。そのぶん読みにくくなりましたが、どこの現場にも当てはまる話になったはずです。

## 話す二人

柊は基盤チームのエンジニアで、3つの夜すべての当事者です。ふだんは落ち着いて時系列に沿って話す人ですが、どの夜も落ち着いてはいられなかったと本人は言っています。

真砂は別チームの所属で、ポストモーテムの会の司会をしています。対応には加わっていないぶん、素朴な質問を投げかけます。そしてその素朴な質問が、たいてい核心を突いています。

## この本に出てくる用語

| 用語           | この本での意味                                                 |
| -------------- | -------------------------------------------------------------- |
| レジストリ     | 依存パッケージを配布するサーバー。社外のものも社内のものもある |
| ロックファイル | どの依存をどのバージョンで入れるかを固定した一覧               |
| キャッシュ     | 一度取得したものを次回以降も使い回すために保存しておく複製     |
| キャッシュキー | どのキャッシュを復元するかを決める文字列                       |
| ランナー       | CIのジョブを実際に実行する、使い捨てのマシン                   |
| キュー         | 処理待ちのタスクを順番にためておく仕組み                       |
| ワーカー       | キューからタスクを取り出して処理する常駐プログラム             |
| 冪等           | 何度実行しても結果が変わらないこと                             |

用語の説明は最小限にとどめました。分からない用語が出てきても、その段落は仕組みの説明としてではなく、二人がどこで判断を誤ったかの話として読んでください。どこで誤ったかは、用語を知らなくてもたいてい分かるはずです。
