# 夜話のあとに {#night-4}

<p class="chapter-lead">二〇二六年十一月四日／振り返りの会にて</p>

## 三つ並べてみる

<div class="dialogue">

<span class="speaker">真砂</span>三つ話し終えたので、最後に並べてみたい。順番に聞いていて、途中から同じ話に聞こえてこなかった？

<span class="speaker">柊</span>聞こえた。落ちた場所は毎回違うのに、つまずき方が同じ。

<span class="speaker">真砂</span>整理するとこうなる。

</div>

<div class="inset">

| 夜                                                         | 落ちた場所     | 疑われなかった前提         |
| ---------------------------------------------------------- | -------------- | -------------------------- |
| <a href="04-night-1.html#night-1" data-ref="chap-num"></a> | 通知ワーカー   | 緑は正常であること         |
| <a href="05-night-2.html#night-2" data-ref="chap-num"></a> | 日次集計バッチ | 処理は一度しか走らないこと |
| <a href="06-night-3.html#night-3" data-ref="chap-num"></a> | CIのビルド     | キャッシュは最新であること |

</div>

<div class="dialogue">

<span class="speaker">柊</span>右の列、どれも当日は誰も口に出してない。

<span class="speaker">真砂</span>口に出さないから前提なんだよね。確かめたことがないものだけが、この列に入る。

<span class="speaker">柊</span>そして三つとも、確かめる手間は十分もかからなかった。キューを見る、実行回数を数える、キャッシュを切って流す。全部十分以内。

<span class="speaker">真砂</span>その十分に、それぞれ何時間か遅れて到達している。

</div>

<div class="note">

三つの障害で、原因の特定に費やされた時間は合計で八時間半、修正そのものに要した時間は合計で四十分だった。この比率は特別ではない。多くの現場で、障害対応の時間はほとんどが「どこを見るか」を決めるために使われている。

</div>

> 直すのは速い。見る場所を決めるのが遅い

## 行き詰まったときの五つの問い

<div class="dialogue">

<span class="speaker">真砂</span>それで、この本のためにまとめを作った。手が止まったときに読む五つの問い。

<span class="speaker">柊</span>順番に効くというより、どれか一つが刺さればいい、という並べ方にしてる。

</div>

1. いま見ている画面は、いつの時点のものか。
2. その正常は、何を測った結果か。測っていないものを正常と呼んでいないか。
3. 動く場所と動かない場所で、違うものは何か。壊れているかどうかは考えずに書き出す。
4. 最後に成功したのはいつで、そのあいだに何が変わったか。自分たちの変更以外も含めて。
5. まっさらな状態からやり直すと、どうなるか。それを試すのに何分かかるか。

<div class="dialogue">

<span class="speaker">柊</span>四番目に「自分たちの変更以外も含めて」と入れたのは、三つめの夜のせい。

<span class="speaker">真砂</span>三週間前の高速化ね。あれ、当日の変更を追うだけでは絶対に出てこない。

<span class="speaker">柊</span>出てこない。引き金を引いた人と、銃を置いた人が別なんだよ。しかも両方とも、まったく正しい仕事をしてる。

<span class="speaker">真砂</span>五番目の「何分かかるか」は。

<span class="speaker">柊</span>切り分けの手段は、速くないと使われないから。三十分かかる確認は、深夜二時には選ばれない。だからキャッシュなしで再実行するボタンを作った。

</div>

<div class="note">

障害対応の速さは、担当者の知識よりも、切り分けに使える手段が何分で終わるかに左右される。三つの夜のあと、この現場に追加されたものの多くは監視や修正そのものではなく、確認を速くするための道具だった。

</div>

## 次の夜まで

<div class="dialogue">

<span class="speaker">真砂</span>最後に、これから同じ夜を迎える人に何か。

<span class="speaker">柊</span>特別なことは何もしていない、とだけ。三つとも、ログには最初から答えが書いてあった。読める形になっていなかっただけで。

<span class="speaker">真砂</span>読める形にするのが仕事、ということか。

<span class="speaker">柊</span>そう思ってる。それと、朝には終わる。三回とも終わったから、これは経験として言える。

<span class="speaker">真砂</span>いい締めだ。次の号でまた話そう。

<span class="speaker">柊</span>次がないことを願ってるけどね。

</div>

<div class="note">

本書の収録は二〇二六年十一月四日、社内の振り返りの会に続けて行われた。次号では、この現場が「復旧手順を書いたのに誰も読まなかった」問題にどう向き合ったかを扱う予定である。
</div>
