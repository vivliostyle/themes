# はじめに {#intro}

この本は、社内で起きた三つの障害を、当事者の柊と、聞き手役の真砂が振り返った記録です。ポストモーテムの会で録った音声を、読める長さに刈り込んで並べました。

三つとも、原因がいつもの場所にありませんでした。監視は緑のまま、テストは全部通ったまま、コードは一行も間違っていないまま、それでもサービスは止まり、数字は狂い、ビルドは赤くなりました。犯人探しの本ではありません。行き詰まった二人が、どこで問いの立て方を変えたのか。その一点だけを残そうとしています。

## この本の読み方

太字の名前が付いた段落が、二人の発言です。名前は左の欄にぶら下げてありますから、目で追うときは名前の列だけを拾ってください。誰が話しているかは、それでだいたい分かります。

字下げしたグレーの段落は編集部の補足です。当日の記録や、あとで分かった事実のうち、対話のなかでは触れられなかったものをここに置きました。話の腰を折る位置にありますが、飛ばして読んでも筋は通ります。

社名、製品名、社内の呼び名はすべて伏せ、一般的な言い方に置き換えています。レジストリ、CI、キュー、ワーカーといった素っ気ない言葉が続くのはそのためです。読みにくさの分だけ、どこの現場にも当てはまるようになったと思ってください。

## 話す二人

柊は基盤チームの担当で、三つの夜のいずれも当事者でした。落ち着いて時系列から話しはじめる人ですが、当日は落ち着いていなかったと本人は言っています。

真砂は別チームの所属で、ポストモーテムの会の司会をしています。自分では手を動かしていないぶん、素朴な質問をします。この本では、その素朴な質問がだいたい正しい方向を向いています。

| 言い方         | この本での意味                                   |

| ワーカー       | キューから仕事を取り出して処理する常駐プログラム |
| 冪等           | 何度実行しても結果が変わらないこと               |

</div>

用語の説明は最小限にとどめました。分からない言葉が出てきたら、その段落は仕組みの名前ではなく、二人がどこで判断を誤ったかを読んでいると思ってください。誤り方のほうは、たいてい言葉を知らなくても分かります。
